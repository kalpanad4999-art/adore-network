# Project architecture
- Store member reference photos in the private `member-photos` bucket under `{ownerId}/{memberId}/`; keep only the path on the existing member record so private media is never exposed publicly.
- Keep photo recognition behind `src/lib/photoAttendance.ts` and never fabricate matches; recognition remains local to the browser during refactors.
- Write reviewed attendance to the existing `attendance` table keyed by member and date; its unique constraint prevents duplicate records.
- Validate reference-photo face count on-device before upload, and keep identity matching local using the existing browser implementation; this avoids third-party photo processing.
- Run face recognition in the browser with face-api (models in /models); store only 128-number descriptors in member_face_enrollments under workspace RLS so photos never go to a third-party service.
- Put Members backend/storage calls in feature services, loading/subscriptions in hooks, pure validation in rules and contracts in types; this isolates backend changes from the existing screen.
- Preserve member save/rollback and payment-first deletion ordering during refactors; these multi-step operations are not transactions and reliability changes require separate approval.
- Keep current page entry points, shared UI, global contexts, auth callbacks and public registration RPCs until their own approved phase; this limits regression risk.
- Do not expose query builders from feature services or manually edit generated integrations/configuration; named operations make future API replacement explicit.
- Test extracted rules/workflows independently of model inference and report live checks separately; mocks do not verify recognition, storage or deployed permissions.
- Map authentication and function failures through `src/lib/authErrors.ts`; this keeps email, phone, OAuth, and recovery errors accurate and consistent.
- Keep the intro in `src/components/intro` as a timed visual overlay with a lazy-loaded R3F scene, image-texture relief and scoped CSS palette; mount the existing app underneath and bypass recovery/public links so branding never delays authentication or changes routes.
- Share renewal queries, expiry rules and live refresh through the layout's renewal data context; keep notification dismissal identifiers scoped to workspace and user in browser storage so notifications never mutate payment reminder history.
